## Live Presentation Sequence (10–15 Minutes)

### Step 1: System Overview & Problem Statement
1. Open browser to `http://localhost:3000`.
2. Introduce the core challenge:
   - Mobile and IoT edge devices face strict battery and CPU bottlenecks.
   - Offloading everything to Cloud incurs high WAN round-trip latency and costs.
   - Offloading everything to Edge risks queue saturation and congestion.
   - **Solution**: An AI-driven Deep Q-Network that dynamically optimizes multi-objective trade-offs (Latency, Energy, Cost, Queue, Deadlines) in real time.

### Step 2: Cinematic 3D Architectural Walkthrough
1. Scroll down the landing page to trigger the choreographed 3D camera transitions:
   - **Act I: The Edge Nexus** — Explain the three-tier paradigm (Mobile Local, Edge Node, Central Cloud).
   - **Act II: Local Constraints** — Highlight battery drain and CPU throttling on mobile hardware.
   - **Act III: Proximity Edge** — Show fog nodes providing low-latency compute with finite queue capacity.
   - **Act IV: Hyperscale Cloud** — Show central cloud providing massive throughput penalized by WAN distance.
   - **Act V: The Neural Arbiter** — Introduce the 17-dimensional state vector and DQN decision engine.

### Step 3: Interactive Simulation (/simulation)
1. Click **ENTER SIMULATION** or navigate to `http://localhost:3000/simulation`.
2. Point out the **2x2 Technical Parameter Grid**:
   - **TASK**: Data Size (MB), CPU Demand (%), Memory (%), Deadline (ms), Priority (1–5).
   - **LOCAL**: Available CPU, Available Memory, Battery Level (%), Base Latency (ms).
   - **EDGE**: CPU Load (%), Task Queue Length, Network RTT (ms), Bandwidth (Mbps).
   - **CLOUD**: CPU Load (%), Task Queue Length, WAN RTT (ms), Bandwidth (Mbps).
3. Select preset **"EDGE HEAVY"** or **"BALANCED NORMAL"**.
4. Click **RUN SIMULATION**.
5. Show live decision badge:
   - Point to `DQN AGENT (XX%)` badge in the bottom rail.
   - Highlight the **Boltzmann Softmax confidence score** (e.g., $38.4\%$).
   - Show the comparative scores for LOCAL, EDGE, and CLOUD.
   - Read the explainable rationale quote generated by the backend:
     *“DQN agent selected LOCAL with 38.4% confidence. Ample local device resources (45.0% CPU available) and zero network overhead provide the lowest simulated execution cost...”*
6. Demonstrate adaptive intelligence:
   - Reduce Local CPU Available to `15%` and increase Task CPU to `85%`.
   - Click **RUN SIMULATION**.
   - Show that the DQN shifts the placement to **EDGE** or **CLOUD** to prevent local CPU deficit throttling!

### Step 4: Fallback & Fault-Tolerance Demo (Optional / High-Mark Feature)
1. In Terminal 1, stop the backend (`Ctrl+C`).
2. On `/simulation`, click **RUN SIMULATION**.
3. Point out the amber badge: `OFFLINE FALLBACK`.
4. Explain: *“The architecture features zero single-point-of-failure; when the neural service is disconnected, the client automatically defaults to the deterministic multi-criteria heuristic.”*
5. Restart Terminal 1 backend.

### Step 5: Research & Empirical Benchmarking (/research)
1. Navigate to `http://localhost:3000/research`.
2. Emphasize **Academic & Scientific Integrity**:
   - Show that all charts load actual empirical data from 5 deterministic seeds (`[42, 101, 2024, 777, 8888]`) and 500 workloads (3,000 policy executions).
3. **Section 01: Experiment Configuration**: Show the 17-D state dimensions, reward weights ($w_L=0.35, w_E=0.25, w_C=0.15, w_Q=0.10, w_D=0.15$), and checkpoint metadata.
4. **Section 02: DQN Action Distribution**:
   - Show that DQN converged to a realistic hybrid policy: **$85.0\%$ Local, $10.8\%$ Edge, $4.2\%$ Cloud**.
   - Explain why: local execution has zero network delay for small tasks; edge is selected when local compute is strained; cloud is reserved for compute-heavy, deadline-tolerant tasks.
5. **Section 03: Performance Comparison Table**:
   - Show the 6-policy benchmark: DQN vs Rule-Based Greedy vs Local-Only vs Edge-Only vs Cloud-Only vs Random.
   - Toggle between **Statistical Aggregates (Mean ± 95% CI)** and **Relative Differences vs DQN**.
   - State the honest research finding:
     *“DQN decisively outperforms all static baselines (+11.9% latency reduction over Local-Only, +14.8% over Edge-Only, +56.7% over Cloud-Only), while achieving a slightly lower monetary cost index (0.066 vs 0.069) than the expert heuristic by prioritizing local execution where possible. In latency, the heuristic maintains an 8.96% advantage under the 200-episode training budget.”*
6. **Section 04: Training Convergence Trajectory**:
   - Show the 200-episode reward curve and monotonic exploration decay ($\epsilon: 1.0 \to 0.05$).
7. **Section 05 & 06: Empirical Findings & Limitations**:
   - Conclude by discussing real-world wireless shadowing, discrete vs fractional offloading, and future directions.

## Post-Demo Q&A Quick Answers

- **Q: Why does Cloud-Only have such a low feasibility rate (21.2%)?**  
  *A: The WAN network round-trip time (40–120 ms) consumes most of the deadline budget before computation even begins, causing interactive tasks with deadlines <100 ms to fail.*
- **Q: Why doesn't DQN beat the Rule-Based Greedy heuristic on latency?**  
  *A: The Rule-Based Greedy heuristic evaluates the exact cost function with omniscient knowledge of current queue state and network delays for each individual task. The DQN approximates this continuous function using 200 training episodes, achieving 91% latency parity without hardcoded decision trees.*
- **Q: Is the model running on GPU or CPU?**  
  *A: The model runs on CPU using PyTorch, requiring less than 5 ms inference time, making it lightweight enough to run directly on an edge gateway or mobile orchestrator.*
